### ج. بوابات النظام الداخلية (Internal Portals)
- **بوابة الإدارة (`/admin/*`)**: 23 موديولاً مكتملة (اللاعبون، المدربون، الاشتراكات، الحضور، التقارير، الرقابة المالية، الفروع). **النقص الحالي:** استبدال البيانات التجريبية (`mockSelectors`) بـ REST API أو Firestore.
- **بوابة اللاعب (`/player/*`)**: محمية بـ `PlayerSessionProvider`. تحتوي على الجدول، كشف الحضور، تقييم الأداء، الشهادات والإنجازات.
- **بوابة ولي الأمر (`/parent/*`)**: إدارة حسابات الأبناء، الاشتراكات، المدفوعات، والجداول.
- **بوابة المدرب (`/coach/*`)**: تسجيل حضور الحصص، تقييم اللاعبين، إدارة المجموعات التدريبية.

## 2. نظام الخطوط والطباعة (Typography & Font Stack)

الخطوط محملة رسمياً في `index.html` وتعمل بنظام التوافق العالي:

### أ. الخطوط المعتمدة
1. **العنوانين باللغة العربية**: `Cairo` (الأوزان: 600, 700, 800, 900) و `Tajawal` (الأوزان: 700, 800, 900).
2. **النصوص والقوائم العربية**: `Cairo` (الوزن: 400, 600) و `Tajawal` (الوزن: 400).
3. **العناوين باللغة الإنجليزية**: `Outfit` (الأوزان: 600, 700, 800, 900) و `Cinzel` للرمزية الأولمبية الفاخرة.
4. **النصوص العامة بالإنجليزية**: `DM Sans` (الأوزان: 400, 500, 600, 700).
5. **الأرقام التقنية والأكواد والأسعار**: `DM Mono` مع خاصية `font-variant-numeric: tabular-nums;`.

### ب. النواقص والتوصيات في الخطوط:
- **تحسين FOUT (Flash of Unstyled Text)**: إضافة `@font-face` احتياطي محلي في ملف CSS بأسماء `sans-serif` مطابقة لنسب الارتفاع.
- **مقياس الخطوط (Font Scaling)**: دعم `data-font-scale="large"` بشكل كامل في كل نصوص الجداول الإدارية.

## 3. نظام الأوضاع وتفضيلات المستخدم (Theme & Modes Engine)

يعتمد التطبيق على محرك `UiSettingsProvider` الذي يخزن الإعدادات في `uos:ui-settings:v1`:

| الإعداد (Setting) | القيم المدعومة | طريقة التطبيق في الـ DOM | النواقص الحالية |
| :--- | :--- | :--- | :--- |
| **المظهر (Appearance)** | `light` \| `dark` \| `system` | `document.documentElement.dataset.theme` | بعض جداول الإدارة في وضع `light` تحتاج تباين أعلى لخطوط الحواف |
| **اتجاه اللغة (Bilingual Order)** | `en-first` \| `ar-first` | `document.documentElement.dataset.bilingualOrder` | مكتمل بنسبة 100% |
| **الكثافة (Density)** | `comfortable` \| `compact` | `document.documentElement.dataset.density` | تقليص مسافات الحشو داخل جداول الإدارة عند تفعيل `compact` |
| **تقليل الحركة (Motion)** | `system` \| `reduced` | `useReducedMotion()` و `dataset.reducedMotion` | مكتمل في Splash و RouteTransition وقواعد CSS العامة |
| **حجم الخط (Font Scale)** | `default` \| `large` | `document.documentElement.dataset.fontScale` | تطبيق تكبير 1.15x على عناصر المدخلات |

## 4. نظام الكروت الموحدة (Card Architecture)

تم توحيد كروت الواجهة العامة في المجلد `src/components/public/cards/`:

### أ. `SportCard`
- **المعايير**: نسبة أبعاد الصورة `4:5`، حواف نصف قطرها `16px` (`rounded-2xl`)، زجاجي داكن مع بوردر ذهبي خافت `border-amber-500/20`، أيقونة ثلاثية الأبعاد تفاعلية، ومسار التدرج الرياضي (Pathway).
- **النقص للمطور**: إضافة علامة توضح الفئة العمرية المتاحة (مثلاً: 6-16 سنة) في شريط الشارات العلوي.

### ب. `ProgramCard`
- **المعايير**: نسبة أبعاد الصورة `16:9`، شارة المستوى الفني (Level)، وسوم المهارات المستهدفة (Focus Tags)، وزر طلب التسجيل.
- **النقص للمطور**: إضافة شارة حالة المقاعد المتوفرة (Available Seats / Full).

### ج. `ValueCard`
- **المعايير**: تصميم خفيف بدون صور ثقيلة، يركز على الأيقونة الذهبية المتوهجة، رقم الخطوة/المرحلة الترتيبي، وشارة المفهوم.
- **النقص للمطور**: دعم خيار كروت الروابط التشعبية عند النقر الكامل.

### د. `ProductCard` (المتجر)
- **المعايير**: نسبة أبعاد `4:3.4`، شارات أداء أولمبية (Hydro Pro, Match Spec)، ومحدد الألوان التفاعلي، وإضافة سريعة للسلة.
- **النقص للمطور**: عرض نسبة الخصم المئوية عند وجود سعر قديم (`compareAtPrice`).

## 5. الحقول والنماذج والتحقق (Form Fields & Inputs)

### أ. نماذج الموقع والمتجر:
1. **حقول الاتصال (`ContactPage`)**: الاسم، البريد، الهاتف، الرياضة المرغوبة، والرسالة.
2. **حقول إتمام الطلب (`CheckoutPage`)**:
   - الشحن: الاسم الكامل، رقم الهاتف، العنوان التفصيلي، المدينة، الإمارة/المنطقة، الرمز البريدي.
   - الدفع: اختيار وسيلة الدفع (بطاقة ائتمان، دفع عند الاستلام، تحويل بنكي).
3. **حقول البوابات (`PortalAuthPage`)**: تسجيل الدخول بالهاتف مع التحقق بـ OTP ورسائل الخطأ المباشرة.

### ب. النواقص الفنية في الحقول (Developer Checklist):
- [ ] **التحقق من صحة المدخلات (Client-side Validation)**: توحيد مكتبة التحقق باستخدام `zod` أو خطافات React Hook Form لجميع الحقول.
- [ ] **أقنعة الهواتف (Phone Input Masking)**: إضافة كود الدولة الموحد (+971 للإمارات / الدولي) مع فحص عدد الخانات تلقائياً.
- [ ] **حالة التحميل في الأزرار (Button Loading State)**: إضافة مؤشر دوران (Spinner) داخل زر الإرسال لمنع الإرسال المزدوج.
- [ ] **إمكانية الوصول (ARIA Labels)**: التأكد من وجود `aria-describedby` لكل حقل يشير إلى نص رسالة الخطأ المرافقة له.
